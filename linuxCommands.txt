sudo systemctl restart systemd-logind
    Executing sudo systemctl restart systemd-logind is a powerful command that manages user logins and active sessions,
    but running it on a desktop system can cause unexpected disruptions.Here is exactly what this command does, what to
    expect when you run it, and safe alternatives.What the Command DoesThe systemd-logind service is a background daemon
    responsible for tracking user logins, managing active seats, handling power button presses (like sleeping or shutting down),
    and handing out device permissions to graphical sessions.Restarting this service forces the operating system to completely
    tear down and reload its login tracking framework.The Immediate Risks (Desktop Systems)If you run this command inside a
    graphical desktop environment (like GNOME, KDE, or XFCE):Sudden Logout: It will immediately terminate your graphical server
    session. You will be violently booted back to your main login screen (GDM, LightDM, SDDM).Data Loss: Any open, unsaved files,
    background terminal operations, or active browser downloads running in that session will be killed instantly without warning.
    Terminal Survives (Usually): If you execute this while logged directly into a physical TTY console (e.g., Ctrl + Alt + F3),
    your session will usually survive, but graphic sessions will still crash.Why People Run This CommandSysadmins and developers
    typically restart this service to fix specific, annoying bugs:Ghost Sessions: To clear out old, frozen user sessions that are
    stuck in the background after a bad SSH disconnect.Broken Power Keys: To fix issues where your computer refuses to go to sleep,
    suspend, or shutdown when you close the laptop lid or press the power button.

    Configuration Reloads: To instantly apply new tweaks made inside the /etc/systemd/logind.conf configuration file.
    Safe Ways to Use It
    1. The Safe Alternative: Configuration ReloadIf you just edited the logind configuration file and want to
    apply the changes without kicking yourself out of your desktop, use this safer command
    instead: bashsudo systemctl reload systemd-logind Use code with caution.
    Note: This signals the daemon to reread its configuration files without shutting down the active login seats.
    2. Before You Run a Full RestartIf you absolutely must run the full restart command:Save all open documents and close
    your applications.Bookmark any critical web browser tabs.Make sure you are not running any long-term terminal scripts
    or file transfers in the background.


systemctl is-active
    systemctl is-active command checks whether a specific system service or background process is currently running and operational
    on your Linux machine.
    e.g.  systemctl is-active docker
          The Outputs:
            active: The service is running fine right now.
            inactive: The service is completely stopped.
            failed: The service crashed or failed to start due to an error.


sudo tee /etc/docker/daemon.json << 'EOF'
{
  "data-root": "/home/docker-data"
}
EOF
   The tee command reads data from standard input (your terminal) and writes it to two places at once: it prints it to
   your screen and saves it into a file. The name comes from a physical plumbing T-splitter (Tee), because it
   splits a single stream of data into two separate directions.The tee command reads data from standard input (your terminal)
   and writes it to two places at once: it prints it to your screen and saves it into a file. The name comes from a physical
   plumbing T-splitter (Tee), because it splits a single stream of data into two separate directions.

   The above command uses tee combined with sudo and a text block (<< 'EOF' ... EOF) to safely write configuration
   settings into a protected system file.
   Here is the exact step-by-step breakdown:
   << 'EOF' ... EOF (Here-Doc): This groups all the text inside the block (the JSON data configuration) and feeds it into
   the tee command as input.
   sudo tee: Runs the writer process with root privileges.
   /etc/docker/daemon.json: This is a protected system folder. Normal terminal commands like
   echo "{...}" > /etc/docker/daemon.json will fail with a "Permission Denied" error—even if you put sudo at the very
   front—because the redirection arrow (>) is executed by your standard shell user, not root.
   sudo tee completely bypasses this limitation.

sudo du -sh /var/lib/docker.old
   The sudo du -sh command tells you exactly how much disk space a specific file or folder is taking up on your hard
   drive, running with administrator privileges so it doesn't get blocked.
   Here is the exact piece-by-piece breakdown of how it works:
   1. The Permissions Part
       sudo (Superuser Do): Runs the command as the root administrator. This is absolutely necessary when
       checking system directories (like /var/lib/docker.old), because normal users are blocked from looking inside them for
       security reasons. Without sudo, the command would spit out hundreds of "Permission Denied" errors.
   2. The Core Command
       du (Disk Usage): This is the core utility tool. Its only job is to measure the space occupied by
       files and directories on your Linux file system.
   3. The Option Flags
      -s (Summary): Tells the tool to give you just the final total size of the folder. Without this flag,
       du will print every single file, subfolder, and image layer inside that directory on a separate line, creating a massive
       wall of text.
       -h (Human-readable): Converts raw blocks into clean, universal units that humans can understand instantly. Instead of
       showing a confusing raw number like 42894336 (bytes), it automatically adds format labels like 41G (Gigabytes) or
       350M (Megabytes).
